# 应用帧与 WebSocket 协议

本文记录**当前代码实际行为**，包括尚未完善的语义。依据：[band_config.h](../firmware/include/band_config.h)、[frame_codec.c](../firmware/src/frame_codec.c)、[uplink.c](../firmware/src/uplink.c)、[ring_buffer.c](../firmware/src/ring_buffer.c)、[ws_client.c](../firmware/src/ws_client.c)。

运行方法见 [BUILD_AND_TEST.md](BUILD_AND_TEST.md)，2026-10-02 真实本地 TCP 联调的通过记录见 [VERIFICATION.md](VERIFICATION.md)。本文不是完整 RFC 兼容性或生产协议保证。

## 1. 分层与消息边界

```text
应用帧 / TLV -> WebSocket binary payload -> TCP
                                    主机：socket
                                    STM32 适配方向：USART + Wi-Fi AT
```

`uplink_send()`用 binary WebSocket 消息发送编码后的应用帧。接收回调不区分 text / binary，均把消息内容逐字节喂给应用解码器，因此允许应用半帧跨消息、一个消息包含多帧。互操作时应使用 binary，避免把任意二进制数据当作 UTF-8 text。

## 2. 应用帧字节布局

多字节整数统一小端，载荷字段另有说明时除外。

| 偏移 | 字节数 | 字段 | 说明 |
| --- | ---: | --- | --- |
| 0 | 1 | SOF0 | `0xAA` |
| 1 | 1 | SOF1 | `0x55` |
| 2 | 1 | TYPE | 消息类型 |
| 3 | 2 | SEQ | 16 位序号，低字节在前 |
| 5 | 2 | LEN | 应用载荷长度，低字节在前 |
| 7 | LEN | PAYLOAD | 最多 256 B |
| 7 + LEN | 2 | CRC16 | 低字节在前 |

总长为 `9 + LEN`，最大 265 B。CRC16/CCITT-FALSE 使用多项式 `0x1021`、初值 `0xFFFF`、不反射、最终异或 `0x0000`，覆盖 `TYPE + SEQ + LEN + PAYLOAD`，不覆盖 `AA 55`和 CRC 字段。测试向量：ASCII `123456789`得到 `0x29B1`，线上字节为 `B1 29`。

解码器支持逐字节输入、半包 / 粘包、帧头重新同步，拒绝超长载荷和 CRC 错误。CRC 错误更新统计；上行接收路径还累加 `param_errors`，但**不会自动回复 NACK**。

### 类型与实现状态

| 类型 | 常量 | 当前行为 |
| --- | --- | --- |
| `0x01` .. `0x05` | 单项心率 / 步数 / 温度 / 电池 / 姿态 | 常量及类型名存在；当前应用周期发送聚合包 |
| `0x06` | `MSG_HEALTH_BATCH` | 当前应用上传的聚合数据 |
| `0x10` | `MSG_ACK` | 解析载荷序号并确认缓存记录 |
| `0x11` | `MSG_NACK` | 只累加否定确认统计 |
| `0x20` | `MSG_PARAM_SET` | TLV 参数解析与部分参数存储 / 应用 |
| `0x21` / `0x22` | 参数查询 / 参数报告 | 有常量和编码辅助函数，但无自动查询分发 / 回复 |
| `0x23` | `MSG_TIME_SYNC` | 长度至少 4 B 时计数并触发参数回调；未解析时间或写 RTC |
| `0x30` | `MSG_OFFLINE_BATCH` | 有常量；当前补传保持原始帧类型，不重包为此类型 |
| `0x40` / `0x41` | 应用 PING / PONG | PING 载荷原样回 PONG，但分配新的发送序号 |
| `0x80` | `MSG_LOG` | 有常量；不代表自动日志上传 |
| `0x90` | `MSG_OTA_BEGIN` | 预留；没有完整 OTA 流程 |

未知类型经过帧解码后会计入 `rx_frames`，当前分发默认忽略，不自动发 unsupported ACK。

## 3. 聚合数据 `0x06`

`frame_pack_health()`按字段编码，载荷长度固定为 17 B，**不是直接发送 C 结构体内存**。当前解包函数要求至少 17 B，读取前 17 B，不拒绝额外尾字节。

| 载荷偏移 | 类型 / 字节数 | 字段 | 单位 / 说明 |
| --- | --- | --- | --- |
| 0 | u8 / 1 | heart_rate | 协议命名为 bpm，当前应用是运动峰值估算 |
| 1 | u8 / 1 | confidence | 算法置信字段，不是医学置信度 |
| 2 | u16 / 2 | rr_interval_ms | 协议命名为 RR，当前来自峰值 / 步频换算 |
| 4 | i16 / 2 | temperature_c100 | 0.01 °C；当前应用输入红外对象温度 |
| 6 | u16 / 2 | steps | 16 位累计步数，超过范围会回绕 |
| 8 | u16 / 2 | battery_mv | mV |
| 10 | u8 / 1 | battery_pct | 百分比估计 |
| 11 | i16 / 2 | roll_c100 | 0.01 度 |
| 13 | i16 / 2 | pitch_c100 | 0.01 度 |
| 15 | i16 / 2 | yaw_c100 | 0.01 度 |

默认上传周期为 5000 ms，可由 TLV 修改。字段名保留了原型接口命名，不能据此声称真实心搏检测、核心体温测量或诊断认证。

## 4. 序号、ACK 与离线补传

### 4.1 序号与发送返回值

`uplink_send()`从 1 分配 16 位发送序号，回绕时跳过 0。成功编码后序号前移；离线缓存失败也不撤销该序号。

| 返回值 | 含义 |
| --- | --- |
| `0` | 在线发送函数成功，不等于服务端落库或 ACK |
| `1` | 已写入离线缓存，待补传 |
| 负数 | 参数、编码、容量等错误 |

SEQ 没有设备身份或持久启动代号，重启会重新编号。真实业务去重不能只把短序号当作永久唯一键。

### 4.2 ACK 载荷

```text
status u8 | ack_seq u16 LE
```

标准载荷为 3 B；当前解包函数接受至少 3 B，忽略额外尾字节。被确认的是**载荷中的 `ack_seq`**，不是 ACK 帧头的 SEQ。

状态常量为 `0=OK`、`1=CRC_ERR`、`2=SEQ_DUP`、`3=UNSUPPORTED`、`4=PARAM_ERR`。当前接收逻辑先调用 `resend_ack(ack_seq)`，尝试移除该条缓存，再检查 status；**即使 status 非零，也不会保留记录等待重试**，只另外累加 `nacks_rx`。

ACK 序号未命中缓存会增加 `dup_acks` / `dup_suppressed`。由于在线成功直发并不留缓存，正常在线 ACK 也可能计入这些统计，不能将计数直接解释为网络重复 ACK。`MSG_NACK`当前只计数，不重传指定序号。

2026-10-02 的本地联调收到 9 条 ACK，其中 1 条在线 ACK 未命中缓存；服务端重复序号仍为 0。这体现了客户端未跟踪 ACK 统计与服务端重复数据统计的区别，详细记录见 [VERIFICATION.md](VERIFICATION.md)。

### 4.3 缓存和补传会话

- 64 个 RAM 槽位，每条最多 128 B，保存**编码后的整帧**和相同序号；可缓存载荷最多 119 B。
- 帧编解码允许 256 B 载荷，但超过 119 B 的帧在离线 / 直发失败时无法落入缓存。
- 缓存满覆盖最旧记录并增加 `dropped_total`；没有 Flash / 文件持久化，重启丢失。
- 新补传会话重置 `sent`标志和扫描状态，按缓存插入顺序扫描，每次 `uplink_poll()`最多补传 8 条。
- 补传保留原始 TYPE / SEQ / PAYLOAD / CRC；ACK 精确移除该序号记录，记录及其 `sent`标志一起搬移。
- 发送失败会复位该记录的 `sent`并重新扫描；发送成功但 ACK 丢失则没有同会话超时重试。
- 新连接 / 新会话可以再次发送尚未确认的记录；客户端发送标志不是服务端持久业务去重。
- 会话 ACK 水位线会跳过不晚于水位线的序号，乱序 ACK 可能导致旧的未确认记录在本会话不再发送。
- 在线新数据可能穿插于积压补传；缓存插入顺序不能推出所有线上数据的全局序号顺序。

因此本实现不是 lossless、at-least-once 或 exactly-once 交付保证。容量覆盖、在线无待 ACK 记录、ACK 丢失、非零 status 和重启均存在数据不完整风险。[mock 服务端](../tools/ws_mock_server.py)仅统计重复 / 乱序，不提供持久幂等业务存储。

## 5. 远程参数 TLV `0x20`

### 5.1 格式与解析

```text
TAG 1 B | LEN 1 B | VALUE LEN B
```

最多 16 项，每项 value 最多 32 B。整数使用小端；字符串按字节处理，不附带结尾 NUL，存入参数时补 NUL。

- 重复 tag 使用首次出现的值。
- 截断、非法长度、超过项数、空参数包会拒绝；当前解析器最后核对已消费长度，超过 16 项不会简单忽略。
- 未知 tag 或整数宽度不匹配被忽略；不能用 `params_applied`计数推断所有字段都生效。
- 结构格式合法但数值越界时，该字段不更新并记录参数错误，其他合法字段仍可更新。
- 合法非空包处理完后版本号和 `params_applied`增加，并触发已注册回调；这不是事务型“全成功或全拒绝”。
- 当前没有自动 PARAM_SET ACK，也不会自动返回完整参数报告。

### 5.2 参数表与应用接入

| TAG | 参数 | 载荷 | 接收范围 | 当前应用接入 |
| --- | --- | --- | --- | --- |
| `0x01` | 心率采样周期 | u16 | 100 .. 10000 ms | 存储；未驱动采集周期 |
| `0x02` | 计步灵敏度 | u8 | 0 .. 100 | 存储；未动态调用算法设置 |
| `0x03` | 上传周期 | u16 | 500 .. 60000 ms | COMM 动态读取 |
| `0x04` | 休眠超时 | u16 | 5 .. 3600 s | 只在初始化读取；下发后未重新设置功耗管理器 |
| `0x05` | 显示亮度 | u8 | 0 .. 100 | 存储；未动态接入 SSD1306 |
| `0x06` | 马达允许 | u8 | 0 关闭，非零归一为 1 | 振动辅助函数动态读取；实际 GPIO 驱动仍需集成 |
| `0x07` | Wi-Fi SSID | 字符串 | 最多 31 B | 存储；未触发 AT 重新关联 |
| `0x08` | Wi-Fi 密码 | 字符串 | 最多 31 B | 存储；未触发 AT 重新关联 |
| `0x09` | 设备名 | 字符串 | 最多 23 B | 存储 |

SSID / 密码 / 设备名上限来自目标缓冲区容量减 1，不是 Unicode 字符数。参数没有持久化，初始化回到默认值。

默认整数参数依次为 `1000 ms`、`50`、`5000 ms`、`15 s`、`80`、`1`；默认设备名为 `BAND-0001`。`uplink_encode_params()`编码 `0x01` .. `0x06`和 `0x09`，不编码凭据；其存在不表示 QUERY / REPORT 已有自动处理。

例如把上传周期改为 1000 ms，可使用 TLV 字节：

```text
03 02 E8 03
```

外层仍须封装为完整 TYPE=`0x20`应用帧，再放入 WebSocket binary 消息；示例只是载荷，不是可直接发送的完整帧。

### 5.3 时间同步与两种心跳

`MSG_TIME_SYNC`的注释约定载荷前 4 B 为 Unix 秒，但实现只检查 `len >= 4`、增加统计并调用参数回调，没有解析时间或更新 RTC；应用也未注册该回调。

应用 PING=`0x40`会原样回送载荷，但通过 `uplink_send()`生成新的 PONG 序号。不能依赖 PONG 帧头与 PING 序号相同。它与 WebSocket opcode `0x9` / `0xA`的控制 ping / pong 是不同层。

## 6. WebSocket 客户端行为

### 6.1 握手与发送

- 默认 TCP 端口为 9001，HTTP Upgrade 路径 `/band`，使用版本 13。
- 客户端以 16 B key 做 Base64；校验由 key 与 GUID 经 SHA-1 / Base64 得到的 Accept。
- 当前握手验证使用较宽松的字符串匹配，不是严格完整的 HTTP header 解析和 RFC 合规检查。
- 客户端数据帧使用 `FIN=1`并带 MASK；应用数据走 binary。客户端不做自动发送分片。
- 收到带 MASK 的服务端帧、非零 RSV 或非法控制帧 FIN / 长度会拒绝。
- 支持已测试的部分分片重组，但超过 1024 B 的重组数据会被截断；片段次序和 text UTF-8 校验不完整。

### 6.2 容量

收发缓冲各为 1024 B，线上帧头也占空间；发送入口保守限制载荷不超过 `WS_TX_BUF - 14 = 1010 B`。重组缓冲为 1024 B。

长度编码辅助支持扩展长度字段，不代表运行时能接收任意大消息。单帧能否完整接收还受整个线上帧是否装入缓冲影响，不能把 `WS_MAX_FRAME_PAYLOAD=1024`理解为任意 1024 B WebSocket 帧都能安全处理。

### 6.3 保活、关闭与重连

| 行为 | 实现约定 |
| --- | --- |
| 控制 ping | 距最后发送约 15 s 后发送 |
| pong 超时 | ping 后约 5 s 未收到 pong 转 ERROR |
| 收到控制 ping | 发送带相同载荷的控制 pong |
| ERROR 后重连 | 后续 `ws_poll()`驱动指数退避，基数 200 ms、上限 8 s |
| 重试次数 | 定义了 `WS_RECONNECT_MAX_RETRY=6`，但当前未实际强制最大次数 |
| CLOSED 状态 | 不自动重连，包括收到 close 后进入 CLOSED |
| 关闭流程 | 发送 / 回复 close 后立即断开 TCP，不完整等待双方关闭握手 |

客户端需要明确的首次 `uplink_connect()`来注册链路回调并开始连接；仅初始化和周期轮询 CLOSED 状态不会自动启动。当前应用未接入首次连接，专用 live 客户端则会显式连接。

## 7. 安全及互操作限制

没有 TLS / `wss`、设备身份认证、授权、抗重放或安全参数存储。CRC16 是损坏检测，WebSocket MASK 是协议要求，两者都不是加密或身份认证。Wi-Fi 密码 TLV 不应在不可信链路上传输。

实际服务端应自行解决持久设备身份、会话 / 启动编号、ACK 语义、业务幂等及安全传输。在这些契约补齐并独立验证前，应只在可信本地测试环境使用本原型，不把 mock 结果解释为生产健康数据服务的可靠性证明。
